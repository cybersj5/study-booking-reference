# Правила проекта для Cline

Папку читает Cline: каждый `.md` отсюда попадает в начало разговора как постоянная
инструкция. Это трек А курса. Никакой команды для подключения не нужно, достаточно
положить файл и открыть проект как рабочую папку.

## Что здесь лежит

| Файл | Когда срабатывает |
|---|---|
| `kontrakt-pervym.md` | всегда: порядок Design First нарушают чаще всего |
| `russkaya-tipografika.md` | только при правке `.md` и текстов в коде, через `paths` |

## Как Cline решает, читать правило или нет

Без фронтматтера правило читается всегда. Чтобы правило включалось только на нужных
файлах, в начало добавляется блок с масками путей:

```
---
paths:
  - "**/*.md"
  - "server/src/errors.ts"
---
```

Маски проверяются по файлам, с которыми идёт работа. Правило, которое читается всегда,
занимает окно в каждом запросе, поэтому узкие правила лучше ограничивать.

## Чем это отличается от AGENTS.md

`AGENTS.md` в корне описывает проект: стек, запуск, запреты. Правило здесь описывает
один приём работы. Граница простая: факт о проекте идёт в `AGENTS.md`, повторяющаяся
процедура идёт сюда.

## Про трек Б

У Claude Code и Codex своя папка и свой формат: `.claude/skills/<имя>/SKILL.md`, и там
решение о подключении принимается по полю `description`. Пример лежит рядом,
в `.claude/skills/dobavit-endpoint/`. Cline файлы оттуда не читает, а Claude Code не
читает `.clinerules/`, поэтому в проекте, где работают обоими инструментами, правило
держат в двух местах или ограничиваются `AGENTS.md`, который читают оба.
