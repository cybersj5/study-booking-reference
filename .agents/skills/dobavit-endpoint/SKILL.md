# Добавить эндпоинт

Проект собран методом Design First. Источник истины это `contract/main.tsp`,
файл `contract/openapi.yaml` из него собирается, а `server/tests/contract.test.ts`
читает собранный контракт и требует, чтобы приложение ему подчинялось.

Порядок ниже переставлять нельзя. Если начать с обработчика, `contract.test.ts`
упадёт, и это его работа, а не поломка.

## Шаг 1. Контракт

Правлю `contract/main.tsp`: модель, маршрут, коды ответов. Коды берутся из
существующего `union ErrorCode`, новый код добавляется туда же.

Собираю: `npm run contract:build`. Файл `contract/openapi.yaml` обновится,
коммитить его обязательно.

## Шаг 2. Схемы

Привожу `server/src/schemas.ts` в соответствие с контрактом. Поля API в стиле
`snake_case`, даты это строки «ГГГГ-ММ-ДД», время это строки «ЧЧ:ММ:СС».
Тип выводится из схемы: `export type X = z.infer<typeof xSchema>`.

## Шаг 3. Хранилище и обработчик

Запрос к базе в `server/src/repository.ts`, маршрут в `server/src/routes/`.
Стиль беру из соседнего файла той же папки, а не придумываю свой.
Первая строка обработчика это разбор входа схемой Zod.

## Шаг 4. Клиент

Правлю типы и вызов в `web/src/api.ts`. Компоненты трогаю, только если
изменилось то, что показывается человеку.

## Шаг 5. Тесты

Копирую `shablon-testa.ts` из этой папки в `server/tests/`, переименовываю
по образцу `api.<сущность>.test.ts` и заполняю. Негативные случаи обязательны:
проверка входа, конфликт, отсутствие.

## Шаг 6. Проверка

Выполняю обе команды и показываю вывод целиком:

```bash
npm run typecheck
npm test
```

Пока обе не зелёные, работа не закончена. Сообщение «должно работать» без вывода
команд не считается результатом.

## Чего не делать

- Править `contract/openapi.yaml` руками: он собирается из `main.tsp`.
- Менять `snake_case` на `camelCase` в полях API.
- Добавлять зависимости: стек зафиксирован в `AGENTS.md`, раздел 2.
- Трогать `server/tests/contract.test.ts`, чтобы он перестал падать.
